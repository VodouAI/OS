## Committing from parallel sessions

Multiple agent sessions work in this ONE worktree concurrently. Two incidents on 2026-07-04: a commit swept another session's edited `src/main.rs` (with a `mod` pointing at a not-yet-committed file — HEAD didn't compile from a fresh checkout), and a hot file was rewritten under a session mid-edit. Rules:

1. **Stage explicit paths only.** Never `git add -A`, `git add -u`, or `git add .` — you WILL sweep another session's in-flight work.
2. **Before staging a shared hot file** (`src/main.rs`, `src/daemon.rs`, `MCP-servers/Vodou-Console/src/llm.ts`, `MCP-servers/Vodou-Console/src/index.ts`, `vodou-hook/src/main.rs`), run `git diff <file>` and look for hunks you didn't author. If you find any, stage only your hunks, and say so in the commit message.
3. **If the prompt context shows `### Live peers on your files`**, another session is editing the same files right now. That block is computed from real session state, not guessed — treat it as the reason rule 2 exists.
4. **A `pre-commit` guard blocks self-inconsistent commits** (staged `mod foo;` / relative TS import whose target file isn't in the index). Source: `scripts/commit-guard.py`; bypass only for genuine emergencies with `VODOU_SKIP_COMMIT_GUARD=1`.
5. **A `secret-guard` blocks staging a credential VALUE** (`scripts/secret-guard.py`). It scans `git diff --cached` added lines against `.build/release-pii-patterns.txt`. Bypass `VODOU_SKIP_SECRET_GUARD=1`, but prefer fixing the string: if it is a test fixture, make it not key-shaped; if it was ever real, revoke it.
6. **A `date-guard` blocks staged lines that violate the time canon** (`scripts/date-guard.py`; canon: `PLANS/PLAN-TIME-CANON.md`). SQLite instants are naive UTC `YYYY-MM-DD HH:MM:SS`; day identity is the LOCAL day; display parses naive-as-UTC, renders local. Bypass a true false-positive with `VODOU_SKIP_DATE_GUARD=1`.
7. **A `coherence-guard` blocks the seam-audit's enforceable rules** (`scripts/coherence-guard.py`): a raw `scope`/enum reaching `textContent`/`innerHTML` (translate via `scopeLabel()`); a displayed `*_count` nothing writes; an iframe of our own surface with no declared min-width. When deliberate, say so in the diff — `// COHERENCE-INTENTIONAL: <why>`.
8. **New module + its declaration commit together.** If you add `mod x;` or an import of a new file, that file goes in the SAME commit.

9. **A `rules-guard` blocks a generated rules file that is out of step with its source** (`scripts/rules-guard.py`). `CLAUDE.md`, `.cursorrules` and `.cursor/rules/vodou-policy.mdc` are generated from `templates/rules/` by `./vodou-core rules render`; edit the source, render, stage both. Bypass `VODOU_SKIP_RULES_GUARD=1`.

10. **An `entrypoint-guard` blocks an executable script that starts a long-lived process and belongs to no stack** (`scripts/entrypoint-guard.py`; registry: `stacks.toml`, PLAN-SEAMS P4 / lane canon rule 3). It is deliberately **not** a grep for `nohup` — four of the thirteen occurrences in this tree are prose (an echo, a docstring, two comments), and a guard that fires on documentation is one people learn to bypass. Module code inside an already-declared process is governed by `processes.toml` instead. `scripts/entrypoint-guard.py --audit` grades the whole tree; `scripts/test-entrypoint-guard.sh` proves it fires in both directions. Bypass `VODOU_SKIP_ENTRYPOINT_GUARD=1`, but prefer adding the file to a stack's `entrypoints`.

11. **An `env-example-guard` blocks a generated `.env.example` that disagrees with its manifest** (`scripts/env-example-guard.py`). `.env.example` is generated from `scripts/env.example.manifest.json` by `scripts/sync-env-example.mjs`, the same generated-from-source shape `rules-guard` covers for `CLAUDE.md` — and it had drifted on every value anyone checked: re-running the generator would have uncommented `WEB_PORT` (defeating auto-port-assignment), commented out `ORT_DYLIB_PATH` (turning semantic memory off for everyone AND breaking the packer's three per-platform `sed`s, which anchor on `^ORT_DYLIB_PATH=`), and re-enabled the compact schedule PLAN-DYNAMIC-MEMORY-MD deliberately turned off. Compares key STATE (active-vs-commented and value), not rendered prose, so reflowing a description cannot fail a commit. Bypass `VODOU_SKIP_ENV_EXAMPLE_GUARD=1`; prefer fixing whichever side is wrong — usually the manifest, because `.env.example` is what ships and gets fixed by hand.

12. **An `ext-version-guard` blocks extension code changing without a version bump** (`scripts/ext-version-guard.py`). EX-5 — the readiness audit's only exploitable finding — shipped **nine days late** because nothing asked this: `0.5.97.78` was set on 2026-08-27, five commits then changed the Store build, and the Chrome Web Store kept serving the pre-fix code under a number it had already accepted. The store only enforces that a version is unique **at upload**, so two different builds can share one and nothing complains. Note this is a DIFFERENT question from `verify-extension-version-chain.sh`, which checks that Rust, the gateway and the UI *agree* about a version — they agreed perfectly for all nine days. Staging anything under `extension/<build>/` that reaches a user requires that build's `manifest.json` `version` to be staged AND to differ from HEAD; staging the manifest without moving the value is the exact failure, so it does not satisfy the guard. Excludes mirror the packer's strip list (`test/`, `store-assets/`, `build-icons.mjs`, `README.md`, `*.map`) — a change that cannot reach a user must not demand a bump, or people learn the bypass. Bypass `VODOU_SKIP_EXT_VERSION_GUARD=1`; the fix is to bump all three manifests together and re-run `scripts/pack-vodou-bridge-store.sh`.

13. **A `workspace-guard` blocks live code that reads or writes a hand-maintained workspace file** (`scripts/workspace-guard.py`; GATE 16 of PLAN-CONTEXT-THAT-MAINTAINS-ITSELF). Everything a session reads from `.vodou/workspace/` is generated on a clock now — `MEMORY.md`, `TOOLS.md`, `HEARTBEAT.md` — and reading those is fine: they are receipts of a renderer. The plan's text said "nothing reads" the four retired files; after the build, six live paths did (the console scraped names with a regex, the planner concatenated two of them, the wizard WROTE all four), and the claim had shipped unexamined because nothing checked it. This does: a staged line that builds a path to, reads or writes a workspace `.md` outside the generated set fails the commit, in the three idioms this tree uses (`.vodou/workspace/X.md`, `path.join(wsDir, 'X.md')`, `.join("workspace").join("X.md")`). A one-time carry of an old file into its new owner says so on the line — `// WORKSPACE-MIGRATION-SOURCE` — and that is the only escape. `--audit` grades the whole tree and is what `vodou-core workspace retire` consults before moving anything, so the commit check and the archiver cannot disagree about what a reader is. Bypass `VODOU_SKIP_WORKSPACE_GUARD=1`; prefer reading the owner (a setting, a pin, `render()`).

14. **A `loop-guard` blocks a proactive loop that no registry declares** (`scripts/loop-guard.py`; registry: `loops.toml`, PLAN-PROACTIVE-LOOPS rev 3 P0b / lane canon rule 3 — a loop is a process). Four curation engines already run continuously and each invented its own output path: the contradiction detector reaches a person through an `eprintln!`, the janitor through a `work_logs` row, the hygiene grader through a command nobody types, the entity graph through a click. The registry is the contract that stops the fifth. Enforced: a staged file under `src/loops/` with no `[loops.<name>]` entry; an entry missing a mandatory field; an entry naming a `fixture_*` that does not exist; an entry that invents its own drain (`emits` must be `loop_findings`) or escalates itself to `critical`. **The fixtures are the point** — `fixture_quiet` and `fixture_fresh` are must-not-fire controls, and the live ledger's finding is that *five graders shipped false-positive because none had one*. The registry is read **from the index**, not the working tree: a commit is judged on what it contains. Silent (exit 0, immediately) on any commit staging neither `loops.toml` nor `src/loops/`, which today is every commit. `scripts/loop-guard.py --audit` grades the tree; `scripts/test-loop-guard.sh` proves it fires in both directions (13 cases). Bypass `VODOU_SKIP_LOOP_GUARD=1`, but prefer adding the entry.

15. **A `push-guard` refuses a direct push to `main` or `development`** (`scripts/push-guard.sh`, installed as `.git/hooks/pre-push` by `scripts/install-push-guard.sh`). Changes reach those branches through a **pull request**. Asked for 2026-09-16, the day a session fast-forwarded `main` and pushed 55 commits in one go — its own onboarding fix plus four other sessions' in-flight work (memory/inject changes, extension bumps to 0.5.97.86, the credential masking). Every commit was sound; the problem is that `main` is what releases are cut from and nobody saw them first. In a clone this many sessions share, "push my work" and "publish everyone's work" are the same keystroke. Pushing a FEATURE branch is unguarded — that is the intended path: `git push -u origin <branch>` then `gh pr create --base main --head <branch> --fill` (`gh` is authenticated as VodouAI, `repo` scope). Merging the PR is the user's call, not a session's. Bypass `VODOU_ALLOW_DIRECT_PUSH=1` for a release push or an emergency; using it is a decision to skip review, so say so.

If `.git/hooks/pre-push` is missing (a fresh clone has no hooks), reinstall it — one install covers every worktree, since `.git/hooks` is shared:
```sh
bash scripts/install-push-guard.sh          # bash scripts/install-push-guard.sh --check  to verify
```

If `.git/hooks/pre-commit` is ever missing, reinstall ALL TEN guards — `.git/hooks/` is not versioned, so a fresh clone has none, and reinstalling only the first silently drops the others:
```sh
printf '#!/bin/sh\nROOT="$(git rev-parse --show-toplevel)"\npython3 "$ROOT/scripts/commit-guard.py" && python3 "$ROOT/scripts/secret-guard.py" && python3 "$ROOT/scripts/date-guard.py" && python3 "$ROOT/scripts/coherence-guard.py" && python3 "$ROOT/scripts/rules-guard.py" && python3 "$ROOT/scripts/entrypoint-guard.py" && python3 "$ROOT/scripts/env-example-guard.py" && python3 "$ROOT/scripts/ext-version-guard.py" && python3 "$ROOT/scripts/workspace-guard.py" && python3 "$ROOT/scripts/loop-guard.py"\n' > .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit
```
